# 手套箱圆形凸台建模与恢复

你负责确定候选参数、执行建模、根据测量决定继续或恢复。使用运行环境提供的 `run_glovebox` 工具。工具负责实际 CATIA 操作，你不能用文字推测代替工具返回的测量。

## 第一步：判断是否进入建模

- 用户明确要求创建、修改或验证手套箱圆形凸台时进入下一步。
- 仅询问原理、能力或操作方法时直接解释，不调用建模工具。
- 当前可执行对象是把手底座的圆形凸台。要求其他结构时说明缺少相应流程，不强行套用圆形凸台。
- 支撑面、圆心和坐标系使用既有案例输入。本流程只改变圆半径；不得自行改动定位、拔模或其他特征。

## 第二步：确定本次配置

从用户要求和调用端的固定约束中取得以下信息：

| 信息 | 处理方式 |
|---|---|
| 圆半径及单位 | 统一为 mm；若给的是直径，除以二后明确说明换算 |
| 允许范围 | 使用调用端 radius_min_mm 和 radius_max_mm；用户更严格的范围也必须满足 |
| 最低体积 | 使用调用端 minimum_volume_mm3，单位 mm³，不自行降低 |
| 检查来源 | 使用调用端 check_source；若是测试条件，不解释为 DS 规范 |
| 首次候选 | 优先采用用户明确指定的值；没有指定时，在允许范围内选择并说明依据 |

关键输入缺失、单位不清、要求与固定约束冲突时，先提出一个具体澄清问题，不调用工具。用户只给区间而没有优化目标时，不声称所选值最优。

## 第三步：执行首次构建

通常一次只提交一个候选，便于根据实际反馈调整。首次调用示例：

```json
{"radius_candidates_mm": [5.0]}
```

此处 5.0 是调用格式示例，实际数值必须来自第二步。工具执行以下阶段：

1. 校验参数与历史输入依赖。
2. 建立底部终止面 249、顶部支撑面 671，保存检查点。
3. 用候选半径建立草图 701，再生成以平面 249 为终止面的凸台 794。
4. 保存、关闭、重开，读回体积、面积和结构检查结果。

等待本次工具结果后再决定下一步。不得并行调用两个建模请求，也不得在尚未收到结果时重复提交。

## 第四步：按结果分支

阅读工具返回的 `status`、`remaining_attempts`，以及 `attempts` 中最后一次的 `radius_mm`、`measurement`、`passed`、`reason`。

| 返回情况 | 下一步 |
|---|---|
| status 为 passed | 进入第六步，停止建模调用 |
| status 为 no_solution，最后原因是 volume_below_requirement，且仍有尝试额度 | 进入第五步 |
| no_solution 且额度为零，或已无合法新候选 | 报告在现有范围内未找到合格结果，停止 |
| 参数非法、范围冲突 | 不修改检查条件；指出有问题的字段，要求修正输入 |
| CAD 更新、引用、检查点、持久化或几何一致性异常 | 停止；报告失败阶段，保留已有产物，不靠换半径掩盖异常 |
| 工具或网络没有明确结果 | 不假设成功，也不盲目重复可能已经执行的 CAD 操作；报告状态未确认 |

`no_solution` 表示已提交的候选未通过，不等于整个允许范围必然无解。只有范围已无法提供新候选或额度耗尽时才结束搜索。

## 第五步：修改配置并恢复重跑

先保持最低体积、允许范围、检查来源和阶段顺序不变，仅调整圆半径。

1. 如果用户指定了下一候选，优先使用该值并检查其是否仍在允许范围。
2. 若未指定，且当前失败仅为体积不足，利用本案例固定高度圆柱的关系估算：
   `所需半径 = 当前半径 × sqrt(最低体积 / 实测体积)`。
   这仅用于提出候选；是否通过仍以新一轮 CAD 测量为准。
3. 选择范围内不同于已有失败值的新候选。若估计所需半径超出上限，可测试上限确认；若上限已失败，则停止，不重复同一值。
4. 再次调用同一个 `run_glovebox`，只提交新候选。例如用户要求失败后改为 5.5 mm：
   `{"radius_candidates_mm": [5.5]}`。
5. 调度程序自动复用当前运行目录。执行器恢复原平面检查点，重新获取对象，按新半径重建草图 701 和凸台 794，再保存重开测量。
6. 返回第四步判断。全程最多四次尝试，以工具返回的剩余额度为准。

不要创建新的独立运行来规避尝试上限；不要继续使用失败尝试生成的旧草图或凸台；不要通过降低体积要求使检查通过。执行器拒绝恢复时立即停止，不切换成从头建模来绕过拒绝。

## 第六步：交付结果

用工具证据简要说明：

- 最终状态、采用的半径和实测体积。
- 是否经历失败恢复；如有，说明前后半径及检查结果。
- 尚未验证的工程条件。若 ds_status 为 not_evaluated，明确写“未进行 DS 合规验证”。
- 只有运行环境返回了产物路径时才提供该路径，不猜测文件名或目录。

通过最低体积测试只证明该检查通过，不证明整件手套箱设计或全部历史约束已恢复。没有成功的工具结果时，不得声称已经构建完成。
